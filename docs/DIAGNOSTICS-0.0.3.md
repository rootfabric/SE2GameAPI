# Space Engineers 2 Redis Bridge

Отдельная папка разработки плагина SE2. Версия 0.0.3: обнаружение гридов и устройств, управление миганием трёх Interior Light 0.5 m проверены в игре через Pulsar Modern.

## Мигание света 0.0.3

Плагин переключает `PowerableBlockComponent.Enabled` в потоке серверной сцены и повторно читает `Enabled`/`Working`. Интервал по умолчанию — 1000 мс на фазу (полный цикл около 2 секунд, с точностью опроса 250 мс).

```powershell
.\set-blink.ps1 start
.\set-blink.ps1 stop
.\tests\Test-Blink.ps1
```

Настройки находятся в `%LOCALAPPDATA%\SE2GameAPI\blink.json`, изменения применяются без перезапуска. По умолчанию выбирается единственный грид `Concordia Research Station` и ровно три лампы с именем `Interior Light 0.5 m` и определением `InteriorLight50_PointLightPowerableBlockDefinition`. Неразрывные пробелы в имени нормализуются. Остальные светильники не выбираются. Если имя грида неоднозначно или число ламп не совпало, управление останавливается с `TARGET_MISMATCH`.

Параметры скрипта: `-GridName`, `-LampName`, `-IntervalMs` (500–60000), `-ExpectedCount` (1–100). Без файла настроек мигание выключено. При `stop`, изменении настройки или потере выбранных целей восстанавливаются исходные Enabled-состояния ещё существующих ламп. Ошибка чтения настройки также останавливает мигание. После повторного старта исходные состояния запоминаются заново.

`blink-status.json` содержит свежий статус, требуемую фазу и фактически прочитанные состояния каждой лампы. `blink-<runId>.jsonl` и игровой журнал содержат записи `BLINK`; при восстановлении в игровом журнале появляется `BLINK_RESTORED`. Включённая лампа может не светить при отсутствии питания или отключённом освещении грида.

Перед сохранением/выходом используйте `set-blink.ps1 stop`, если нужно сохранить исходное состояние ламп: при выгрузке сессии ссылки на объекты сбрасываются, восстановление уже выгруженного мира не выполняется. Настройка `enabled` сохраняется между запусками.

Проверка 2026-11-09: `runId=c7d1c9de55c6443784bd5adfd998a1fc`, PID 17296; лампы `9717:1`, `9720:1`, `9723:1`. Подтверждены Enabled/Working=true у всех трёх в фазе ON и false в фазе OFF. Проверена остановка и повторное чтение исходного Enabled=true у всех трёх после восстановления.

## Структура

- `tests/` — проверки heartbeat и снимков гридов в работающей игре.

## Диагностический плагин 0.0.2

`src/Plugin.cs` реализует `Keen.VRage.Core.Plugins.IPlugin`. При загрузке пишет `LOADED`, затем опрашивает контроллер света через `VRageCore.UpdateQueue` каждые 250 мс, а heartbeat и обнаружение гридов — раз в 5 секунд. Одновременно ожидает не больше одного действия основного таймера. При Dispose отключает таймер. Redis пока не реализован.

Результат находится в `%LOCALAPPDATA%\SE2GameAPI\status.json` и в игровом журнале с префиксом `[SE2GameAPI]`. Поля `runId`, `processId`, `utc`, `heartbeats` позволяют отличить текущий запуск от старого файла. Первый heartbeat сохраняется также в `smoke-<runId>.jsonl`.

`src/Game/GridDiscovery.cs` получает `GameAppComponent.ServerSession` и переключается через `Scene.MoveToDCS()` на поток серверной сцены. Раз в 5 секунд читает её `CubeGridComponent` и непосредственное хранилище блоков каждого грида. Подгриды перечисляются отдельно, без повторного включения в состав родителя.

Выходные файлы в `%LOCALAPPDATA%\SE2GameAPI`:

- `grids.json` — актуальный снимок, атомарно заменяемый после каждого успешного сканирования.
- `grids-<runId>.jsonl` — записи `GRID`, `DEVICE`, `GRID_REMOVED` и состояния сканера. Эти же записи поступают в игровой журнал с префиксом `[SE2GameAPI]`.

Для грида записываются имя, runtime ID, общее питание, количество блоков и устройств, количества всех блоков по типам. Для каждого устройства: имя, runtime ID, тип и GUID определения, ячейка в гриде, `functional`, `working`, прогресс строительства и список классов компонентов. Устройством здесь считается блок с `FunctionalBlockComponent` (включая его производные); броня отражается в составе блоков по типам. `functional` и `working` не равнозначны переключателю включения устройства.

Полный состав отдельного грида выводится при первом обнаружении и при изменении его данных. Неизменившийся состав повторно не печатается. При удалении устройства новая запись `GRID` и следующий за ней полный список `DEVICE` заменяют предыдущий состав этого грида. При выгрузке мира снимок очищается; при смене серверной сессии меняется `sessionGeneration`.

Границы: перечисляются загруженные объекты серверной сцены, а не все объекты в файле сохранения. Идентификаторы `DEntity` вида `102:1` действуют только внутри текущей сессии; использовать их нужно вместе с `runId` и `sessionGeneration`. Устойчивые ID между перезапусками ещё не реализованы. Redis пока нет.

## Сборка и запуск

Из PowerShell в папке проекта:

```powershell
.\build.ps1
.\start-smoke.ps1
.\tests\Test-Smoke.ps1
# Продолжить последнее сохранение и проверить состав мира:
.\start-smoke.ps1 -ContinueGame
.\tests\Test-Grids.ps1
```

Перед запуском закройте игру обычным способом. Скрипт не завершает существующую сессию. Путь игры можно передать через `-Game2`. Сборка лежит в `artifacts/plugin/SE2GameAPI.dll`.

На этом компьютере уже подготовлены переносимые инструменты в `artifacts/tools`: .NET SDK 10.0.403 и Pulsar 2.4.3. Они исключены из Git. Для другого компьютера скачайте [Pulsar Windows x64](https://github.com/SpaceGT/Pulsar/releases/tag/v2.4.3), распакуйте в `artifacts/tools/Pulsar`, затем установите официальный .NET 10 SDK через [dotnet-install.ps1](https://dot.net/v1/dotnet-install.ps1) с `-Channel 10.0 -InstallDir <папка проекта>\artifacts\tools\dotnet -NoPath`.

`start-smoke.ps1` копирует DLL в локальные плагины переносимого Pulsar и запускает его с `smoke-profile.xml`. Профиль включает только этот плагин. Автообновление загрузчика, Discord RPC и статистика плагинов отключены аргументами запуска. Файлы игры и параметры запуска Steam не меняются.
