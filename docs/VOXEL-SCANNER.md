# VoxelScanService — прямое чтение и 3D-визуализация

## Статус и область применения

Экспериментальная ветка `feature/voxel-scan-service`. Реализованы сервис, ограниченный
планировщик, адаптер прямого `ReadRange`, транспорт Redis, Python-визуализатор и тесты.
**Игровое испытание и сборка с DLL установленной SE2 ещё требуются.** Тесты с подставным
storage проверяют наш код, но не доказывают соответствие внутреннему API текущей игры.

Нет новых игровых блоков, Python внутри игры, Raycast, чтения материалов, изменения
вокселей или команд движения. Визуализация открывается **в отдельном Python-окне**, не
в игровом HUD. Пример работает и с сохранённым сканом, без Redis.

## Запуск

После переключения ветки собрать/развернуть плагин обычными `build.ps1` и
`start-smoke.ps1` (см. основной README), загрузить мир и оставить Redis локальным.
Затем из корня репозитория:

```powershell
python -m pip install -r examples/requirements-voxel.txt
python examples/voxel_viewer.py --list-grids
python examples/voxel_viewer.py --grid-id "ID_ИЗ_СПИСКА" --radius 32 --record artifacts/voxel-scan.json
```

Выбор по точному уникальному имени:

```powershell
python examples/voxel_viewer.py --grid-name "Scout" --radius 32 --watch
```

`--watch` запускает следующий скан только после завершения предыдущего. Новый скан
привязывается к новой позиции грида; накопления точек в неверной движущейся системе
координат нет. `--fresh` обходит кэш, например после бурения. Для первого теста около
поверхности начать с `--radius 8`. `area_too_large_reduce_radius` требует уменьшить
радиус, а не отключать ограничитель. Радиус задаёт полуразмер **куба** вокруг начала
координат грида, а не сферу. Выравнивание плиток может немного расширить прочитанную
область; окно обрезает показ до запрошенного куба.

```powershell
python examples/voxel_viewer.py --grid-id "ID" --radius 8 --fresh --no-gui --record artifacts/scan.json
python examples/voxel_viewer.py --replay artifacts/scan.json
```

Крест в центре — начало координат выбранного грида на момент запроса. Квадратные
маркеры — ненулевые **отсчёты Content**, не точная коллизионная поверхность. Оси в метрах,
позиции считаются в float64 относительно грида. По умолчанию порог 1 и до 50 000
отображаемых точек. `--threshold` и `--max-points` меняют только отображение, не исходный
скан. В заголовке видны прогресс, число точек и возраст данных.

## Ограничение нагрузки

- Нет запросов — нет чтения storage. Один активный скан, очереди входа/выхода по 8.
- Одна плитка **16×16×16 максимум за проход**, только Content, LOD0, не более 512 плиток
  за запрос и 64 обнаруженных хранилищ. Никакого разреженного семплирования при чтении.
- Используется существующий DCS-проход и **общий** SceneBudget 0,5 мс. Навигация остаётся
  первой. Воксельный этап участвует в ротации с командами/каталогом/телеметрией.
- 0,5 мс — мягкий лимит: уже начавшийся вызов движка нельзя прервать. После чтения дольше
  2 мс сканер делает паузу 1 с. MaxReadMs передаётся в результатах. Это ограничение
  нагрузки, а не обещание производительности на неизмеренной сцене.
- Каталог и привязка сигнатур создаются в отдельном проходе, без чтения плитки в нём.
  Стоимость первого поиска/reflection/JIT также требует измерения на Windows.
- Кэш максимум 512 плиток (~2 MiB сырых данных), TTL 5 с, ключ включает идентичность
  storage, transform, диапазон и доступную revision. Кэш не удерживает игровые объекты
  сильными ссылками. Смена epoch очищает кэш. События изменения storage пока не подключены.
- Кэшированная плитка сохраняет **исходный** MeasuredAtMs. При отсутствии надёжной revision
  рельеф после бурения может оставаться старым до TTL; для проверки изменения нужен fresh.
- JSON, Redis и файлы — не в DCS. При заполненном выходном канале чтение приостанавливается.
  Данные вокселей не добавляются в 5-Гц снимок обычных устройств.
- Чтение живого storage из фонового worker не используется: потокобезопасность SE2 API
  не установлена. Фоновый транспорт видит только неизменяемые DTO и собственные byte[].

## API-адаптер и диагностика

`ReflectionVoxelStorage` связывается с реально загруженной `VRage.Voxels.dll`. Поддержаны
две формы ReadRange: handler с шестью параметрами и storage с IStorageDataProvider плюс
шестью параметрами. Проверяются ref StorageData, Content-флаг, LOD, целочисленные границы,
VoxelRequestFlags, конструктор/Resize и byte Content(Vector3I/ref Vector3I).

Для координат принимается явно обозначенная матрица StorageToWorld/VoxelToWorld либо
метод преобразования storage-координат. **WorldMatrix сущности, центр планеты, масштаб
1 м и семантика координат из SE1 не подставляются догадкой.** Неподдерживаемая сигнатура,
ref-struct буфер, неизвестное преобразование или недоступный provider возвращают
диагностику; они не заменяются нулями, Raycast или тестовой картой.

Обнаружение предпочитает логические voxel-компоненты. При доступности только
VoxelPhysicsComponent результат помечается `physics_components_only`: дальний рельеф
без физических компонентов неизвестен. Это не загрузка всего процедурного мира.

Если результат сообщает `storage_to_world_unavailable`, `storage_reader_unavailable`
или другую несовместимость, снять метаданные **установленной версии**:

```powershell
dotnet run --project tests/VoxelApiProbe -- "D:\SteamLibrary\steamapps\common\SpaceEngineers2\Game2" artifacts/voxel-api.json
```

Утилита выводит типы, конструкторы, поля, свойства, сигнатуры, версию и SHA-256 DLL;
не запускает игру, конструкторы или getters. По этому отчёту уточняется адаптер.
DLL игры не входят в репозиторий и не должны публиковаться. Подтверждённый стек ReadRange:
https://support.keenswh.com/spaceengineers2/pc/topic/50579-process-failure-on-start-loading-into-game
Это стек старой сборки, а не подтверждение ABI текущей установленной игры.

## Протокол Redis

Отдельный протокол v1, основной протокол устройств v2 не меняется.

| Ключ | Содержимое |
|---|---|
| `se2:local:voxels:requests` | Ограниченная клиентом очередь JSON-запросов, TTL 15 с |
| `se2:local:voxels:scan:<requestId>` | JSON статуса и метрики, TTL 5 минут |
| `se2:local:voxels:tile:<requestId>:<index>` | Одна плитка, TTL 10 минут |
| `se2:local:voxels:events` | Pub/Sub уведомления статуса; ключи позволяют восстановиться после потери события |

Запрос: requestId (UUID hex без дефисов), epoch из свежего `se2:local:state`, gridId,
expiresAtMs (не более 120 с вперёд), action=scan, radius=1..128, fresh=false.
Отмена: тот же requestId/epoch, action=cancel. Повторный scan с тем же requestId не
перечитывает мир; результат ищется по тому же ключу. Новый скан требует новый requestId.
Текущий транспорт доверенный, localhost, без разграничения прав между клиентами.

Плитка: index, storageId, min, size=[nx,ny,nz], origin, axisX/Y/Z, content (base64),
measuredAtMs, cached, storageRevision. Длина Content строго nx*ny*nz, индекс
`x + nx*(y + ny*z)`, координата `origin + x*axisX + y*axisY + z*axisZ`.
Массив содержит все отсчёты, включая нулевые. LOD0 не масштабируется автоматически.

Плитка записывается раньше статуса, который объявляет её индекс. Повтор записи после
сбоя Redis идемпотентен. Неуспешные чтения не занимают индексы, но перечислены в issues;
publishedTiles поэтому может быть меньше plannedTiles. Истёкшая/потерянная плитка —
ошибка получения, не пустота. `complete` означает завершение планов доступного каталога,
**не** полное знание пространства; `partial`/`issues` явно обозначают пробелы.
`NavigationSafe=false` всегда: этот слой сбора и отображения ещё нельзя использовать
как доказательство свободного коридора для автопилота.

## Проверки

```powershell
dotnet run --project tests/VoxelTests -c Release
python -m pytest tests/test_voxel_viewer.py -q
```

Первый набор компилирует реальные новые сервис/reader/транспорт, но использует
подставной storage: бюджеты, кэш, revision, TTL, обратное давление, отмена, deadline,
ошибки/unknown, точность transform, реальные reflection-вызовы и упаковка byte[].
Второй проверяет Python-декодирование, world/grid координаты, пороги/лимиты и 3D-отрисовку.
CI намеренно называется **Voxel contracts (no game DLLs)**.

До слияния нужны: сборка с DLL Windows; живой скан воздуха/поверхности/полости;
визуальное совпадение с местностью; fresh после бурения; смена мира и грида; отключение
Redis; сравнение времени DCS без скана и с холодным/кэшированным чтением. Эти проверки
нельзя заменить зелёными тестами на фикстурах. Автопилот эта ветка не меняет.
