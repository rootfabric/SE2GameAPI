# Виртуальный блок автопилота SE2

На каждом гриде регистрируется устройство `autopilot:<gridId>`, тип `autopilot`.
Это виртуальный блок плагина, без модели или нового предмета в меню строительства.
Команда задаёт цель; контур управления целиком работает внутри серверной сцены
плагина с частотой до 20 Гц. Внешний Python только отправляет задания и наблюдает.

## Использование

```python
from secontrol.se2 import Client

with Client(timeout=5) as bridge:
    pilot, = bridge.devices(device_type="autopilot", grid_name="Blue Miner")
    state = pilot.refresh()
    print(state["properties"]["position"])
    receipt = pilot.goto(
        [251860.0, 9072.0, -13813.0],  # абсолютная мировая точка, метры
        forward=[0, 0, -1],           # мировое направление локальной оси -Z грида
        up=[0, 1, 0],                 # мировое направление верха; задаёт крен
        max_speed=3, position_tolerance=.5,
        heading_tolerance_deg=3, timeout=120,
    )
    arrival = pilot.wait(receipt.request_id, timeout=130)
    print(arrival["properties"]["distance"])
    # Для немедленного прерывания: pilot.stop()
```

Пример координат иллюстративный: перед запуском выбрать безопасную точку в своём
мире. Forward — конечная ориентация грида, не вектор скорости; на цели скорость
снижается до нуля. Если forward/up не заданы, сохраняется исходная ориентация.
Параллельные forward/up и нулевые направления отклоняются. Ось -Z относится к гриду,
а не автоматически к направлению конкретной кабины.

`align_course=True` (goto, протокол `alignCourse`) держит нос грида постоянно
направленным по вектору к цели: ориентация пересчитывается каждый тик полёта,
up берётся из параметра up или исходного верха. Флаг взаимоисключим с forward и
недоступен в ground-режиме. В 0.5 м от цели вектор курса вырождается — держится
последняя хорошая ориентация. Проверено в игре: доворот от 178°, в установившемся
полёте отклонение носа от курса 0.0–0.5°.

По умолчанию (`KeepControlOnPlayer=true`, Python `cancel_on_player=False`) вход
игрока в кресло не отменяет миссию: контроллер продолжает подавать ввод, а отказ
`player_has_control` при старте не выдается. При `KeepControlOnPlayer=false`
возвращается старое поведение — миссия отменяется, игрок получает управление.
Игрок в кресле может бороться с контроллером ручным вводом; приоритет ввода
определяет движок. Вход игрока виден в телеметрии (`hasPilot` у кресел).

`confirmed` на goto подтверждает принятие миссии и состояние Navigating. Прибытие
подтверждает отдельный статус Arrived с совпадающим missionId, ошибкой позиции,
угла и скоростью. `wait()` только наблюдает: закрытие клиента/Redis не отменяет
уже начатую миссию. В плагине действует mission timeout 1..600 секунд.

## Как устроен полёт

- Двойная точность мировых координат; ограничение скорости по расстоянию и
  тормозному пути, затем обратная связь по фактической линейной скорости.
- `MaxThrustData.Regular.Positive/Negative` содержат доступные силы по шести
  локальным направлениям. Желаемая мировая сила переводится в координаты грида
  и нормируется по доступной силе каждого направления.
- `ControlData.Movement` передаётся штатному `ThrustComponent`: движок распределяет
  тягу между реально установленными двигателями с учётом их направления, питания
  и ограничений. Плагин не изменяет координаты, скорость или физические импульсы напрямую.
- Ошибка ориентации вычисляется кватернионом, включая разворот на 180°. Через
  `AngularControlData.TargetAngularVelocity` штатные гироскопы поворачивают грид.
- Допуск прибытия должен удерживаться 0,5 с: расстояние, угол, скорость ≤0,25 м/с.
  Затем управляющий ввод снимается и включается штатное гашение скорости.

В основе сравнения с SE1: `SE-MessageBroker-Redis/DedicatedPlugin/Telemetry/Devices/RemoteControlDevice.cs`
вызывает штатный автопилот Remote Control с waypoint и режимами, включая ControlWheels.
В SE2 готовый аналог этого блока на текущих гридах не найден, поэтому планирование
скорости и ориентации реализовано в плагине. Используемые SE2 типы проверены в
установленной Game2.Simulation.dll 4.0.0.3165.

## Наземный режим

`pilot.goto(point, mode="ground", max_speed=3)` включает экспериментальный контроллер
колёс. Алгоритм спроецирует направление к цели на опорную плоскость, рассчитает
знаковую ошибку курса, руление и газ, снизит скорость в повороте и перед точкой.
Используется штатный `WheelCornerModuleComponent` через `ControlData` и
`ControlReferenceOrientation`: движок сам учитывает ориентацию колёс и выбирает
передние рулевые колёса. Стояночный тормоз переключается через `IParkingBrake`.

Сравнение с SE1: `C:/secontrol/src/secontrol/devices/rover_device.py` использует
проекцию на плоскость, PID руления и отдельные команды колёсам с учётом зеркального
монтажа. В SE2 монтаж учитывает штатный WheelContext; знаки ручных SE1 override
не переносятся напрямую.

Текущие ограничения наземного режима: 2..16 колёсных модулей, до 10 м/с и 1 км;
плоский маршрут, остановка при наклоне более 60° от исходного верха. Конечное
направление forward для наземного режима пока отклоняется: требуется отдельный
планировщик подъезда/разворота. Нет объезда препятствий, анализа сцепления или
планирования по рельефу. В текущем мире колёс нет — реальная езда **не проверена**.
Проверены математические знаки руления, проекция и торможение, а в игре — отказ
наземной команды для грида без колёс.

## Ограничения и нагрузка

- Полёт проверен в свободном пространстве на Blue Miner. Полёт в гравитации,
  посадка, стыковка, препятствия и механически связанные гриды отдельно не проверены.
- Нет obstacle avoidance: маршрут — прямая к точке. Текущая версия не предназначена
  для полёта сквозь станцию или автоматической посадки на поверхность.
- Требуются динамический грид, тяга во всех шести направлениях и рабочие гироскопы.
  Пилот в кресле отменяет миссию только при KeepControlOnPlayer=false (по умолчанию
  миссия продолжается). Активный суммарный override, изменение состава грида и потеря
  тяги приводят к отказу/отмене. Изначально выключенные двигатели автоматически не включаются.
  Минимальный допуск позиции — 0.05 м (нужно для стыковки: движковый лимит
  выравнивания коннекторов жёстче, чем магниты SE1 — порядка 0.1 м между пивотами).
- Не более двух активных миссий. Обслуживание циклическое, бюджет общий с другими
  устройствами; между проходами нет поиска блоков или сетевых операций.
- Разрыв выполнения контроллера более 0,75 с отменяет миссию при следующем проходе.
  Он не гарантирует мгновенную остановку во время зависания всей игры.
- Stop, deadline и штатная выгрузка плагина снимают ввод и включают демпферы;
  наземный режим включает стояночный тормоз. Резкое завершение процесса не исполняет cleanup.
- Новый goto при активной миссии отклоняется. Локальный доверенный API не имеет
  многопользовательских прав владения; любой локальный клиент может вызвать stop.

## Проверка

`tests/NavigationTests`: численная модель полёта по всем осям, торможение,
повороты, включая 180°, наземное руление, проекция, недопустимые координаты;
модель автомобиля подтверждает подъезд к точкам слева, справа и позади.

`tests/live_autopilot.py`: Blue Miner перемещается на 5 м, поворачивается на 15°,
возвращается к исходной позиции. Результаты — `autopilot-live-test.json`.
Проверки stop, занятого контроллера и неверных параметров — `autopilot-safety-test.json`.
Эти тесты двигают корабль; перед повторением проверить свободное место вокруг него.

Измерение на реальном коротком тесте: среднее время всей сценовой работы моста
0,15 мс; p95 по гистограмме ≤0,25 мс. Были отдельные проходы до диапазона 2–5 мс.
Это включает другие адаптеры и каталог и не является сравнением FPS с отключённым плагином.
